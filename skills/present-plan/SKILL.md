# Present Plan

זהו שער האישור של מחלקת הפלטפורמה: לפני שכל agent בצוות של
`platform-lead` (או של מחלקת בנייה עתידית) מתחיל לבנות משהו אמיתי,
הוא מפיק דרך ה-skill הזה דשבורד שהמייסד יכול לאשר תוך שניות — לא
לקרוא עמודים של תכנון.

זהו עותק עצמאי, בתוך ה-plugin `business-os` עצמו — לא תלוי בכלים
אישיים מחוץ לתצורת ה-config הזו, כדי שיעבוד באותה מידה תחת כל
CLAUDE_CONFIG_DIR. המייסד יכוונן אותו עם הזמן; אל תשנה את העיצוב
הבסיסי בלי שהתבקשת.

## הערת הקמה חד-פעמית

חבילת Mermaid (`assets/mermaid.min.js`, כ-5.3MB) לא נשמרת ב-git של
ה-plugin הזה — היא גדולה מדי עבור מגבלת ה-commit guard של הרפו
(5MB). אם `render.py` נכשל כי הקובץ חסר, להריץ פעם אחת:

```bash
bash <skill-dir>/scripts/bootstrap-mermaid.sh
```

זה מעתיק עותק מקומי (מ-`~/.claude/skills/visualize-plan` אם קיים) —
פעולה חד-פעמית, לא תלות שרצה בכל render.

## עקרון העל: progressive disclosure

| שכבה | תוכן | ברירת מחדל |
|---|---|---|
| 1 | תקציר מנהלים — 2-3 משפטים | גלוי |
| 2 | תרשים Mermaid | גלוי |
| 3 | טבלת השפעה (לפני/אחרי) | גלוי |
| 4 | פירוט לפי מודול — קבצים, שלבים | **מכווץ** (`<details>`) |
| 5 | צ'קליסט אימות | גלוי |

**חריג יחיד**: חסם שחייב הכרעה לפני שממשיכים (החלטה שעדיין לא
התקבלה, תלות חסרה, סיכון אמיתי) — מקבל `<details open>` משלו בראש
הדף עם badge מסוג `risk`. חסם שמוסתר מאחורי קליק הוא חסם שנשכח.

## מתי מפעילים בלי שמבקשים

בכל פעם ש-`platform-lead` (או agent אחר במחלקת הפלטפורמה) מגיע לנקודה
שבה הוא עומד להתחיל בנייה אמיתית — זה בדיוק הרגע. אל תמתין לבקשה
מפורשת של המייסד; ההצעה עצמה היא הבקשה לאישור.

הצעה קטנה (שינוי של שורה אחת, agent אחד פשוט) לא צריכה דשבורד מלא —
תגיד זאת ותציע להסתפק בתיאור קצר בצ'אט.

## תהליך

### 1. לאסוף את ההצעה

מקור התוכן הוא ההחלטה שגובשה בתוך מחלקת הפלטפורמה: מה בונים ולמה
(מ-`platform-lead`), מה נמצא במחקר (מ-`capability-researcher`), ואם
כבר יש טיוטת מימוש — מה היא כוללת.

### 2. לחלץ את החמישה סעיפים

**תקציר מנהלים** — 2-3 משפטים בעברית פשוטה: איזו יכולת חסרה היום,
מה בונים כדי לסגור את הפער, מה זה מאפשר בפועל. בלי שמות קבצים.

**תרשים** — `flowchart TD` עם 5-12 nodes: מי מפעיל את מי, מה חדש
ומה קיים. זו מפת התמצאות, לא עותק שני של ההצעה.

**טבלת השפעה** — עמודות קבועות: רכיב / המצב כיום / מה ישתנה / סיבת
השינוי. עמודת ה"סיבה" היא זו שנקראת בפועל — הסבר מה קורה בלי השינוי
או מה הוא מאפשר, לא ניסוח מחדש של אותו דבר.

**מודולים** — בלוק מכווץ אחד לכל agent/skill/connector שנבנה: קבצים
ותפקידם, שלבי בנייה קונקרטיים.

**אימות** — איך בודקים שזה באמת עובד (לא רק "נראה תקין") — הפקודות
שיריצו `team-qa` בפועל.

### 3. לרנדר

```bash
python3 <skill-dir>/scripts/render.py /tmp/proposal-content.json -o proposal-preview.html
```

סכימת ה-JSON מתועדת ב-docstring שבראש `render.py` — לקרוא אותו לפני
כתיבת הקובץ. הפלט נוחת בשורש הפרויקט: `proposal-preview.html` +
`mermaid.min.js` לצידו — כדאי להוסיף את שניהם ל-`.gitignore`.

התבנית כוללת `dir="rtl"`, ערכת נושא כהה, כרטיסים, וכפתורי פתח
הכל/סגור הכל, ו-Mermaid **מעותק מקומי, לא מ-CDN**.

### 4. לפתוח

```bash
bash <skill-dir>/scripts/open_in_browser.sh proposal-preview.html
```

מזהה macOS, WSL, לינוקס טבעי ו-Git Bash; מדפיס `file://` אם אין
תצוגה גרפית. עדיף מ-`xdg-open` ישיר — תחת WSL הוא "מצליח" ולא פותח
כלום בפועל.

### 5. לדווח

שורה או שתיים בעברית: שהדשבורד נוצר ונפתח, והיכן. לא לסכם את ההצעה
מחדש בטרמינל — המטרה שהיא כבר על המסך.

## מלכודות Mermaid

- Hebrew תמיד במרכאות: `A["טקסט"]`, לא `A[טקסט]`.
- Node IDs ב-ASCII בלבד.
- שבירת שורה בתוך label: `<br/>`.
- מרכאות כפולות בתוך label: `#quot;`, לא `\"` (לא עובד). עדיף עוד
  יותר — גרשיים עברי אמיתי (״, U+05F4) כשמדובר בקיצור כמו מנכ״ל,
  כי הוא לא מתנגש עם תחביר ה-string של Mermaid בכלל.
- זוויות (`<strategy>`) נקראות כ-HTML בגלל `htmlLabels` — לכתוב
  `:strategy` או להימנע.

```
flowchart TD
    Client["לקוח"] --> API["שכבת ה-API"]
    classDef new fill:#065f46,stroke:#34d399,color:#ecfdf5
    classDef mod fill:#78350f,stroke:#fbbf24,color:#fffbeb
    class API mod
```

## פורמט קטעי ה-JSON

גוף מודול (HTML גולמי, בשדה `body`):

```html
<h4>קבצים</h4>
<ul class="filelist">
  <li><span class="path">agents/example.md</span>
      <span class="why">הסבר קצר</span></li>
</ul>
```

מחלקות זמינות: `filelist` עם `path`/`why`, badges `new` `mod` `del`
`info` `risk`, `<pre><code>` לקוד, `<code>` inline.
