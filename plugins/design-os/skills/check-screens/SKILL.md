# בדיקת מסכים בדפדפן

קריאת קוד לא תופסת את מה שקורה **אחרי** שהדפדפן מרנדר: צבע שנחלש
ב-`opacity`, כלל CSS שחל על תכונה שלא התכוונת אליה, פריסה שנשברת בזום.
ה-skill הזה מריץ Chromium אמיתי ומחזיר ממצאים עם מספרים.

```bash
node ${CLAUDE_SKILL_DIR}/scripts/check_screens.mjs design/ui/<slug>/screens/ --out design/ui/<slug>/screen-check
```

אפשר לתת קובץ בודד, כמה קבצים, או תיקייה. `--no-shots` מדלג על צילומים.
ההרצה הראשונה מתקינה `playwright-core` ו-`axe-core` ל-
`~/.cache/business-os/screen-check` (קוד פתוח, ללא עלות, פעם אחת).

## מה הוא בודק

| בדיקה | מה נתפס |
|---|---|
| `contrast-alpha` | ניגודיות אחרי `opacity` — הצבע המרונדר בפועל. axe לא מכריע על זה |
| `axe:*` | ניגודיות רגילה, ARIA אסור (`aria-label` על `<p>`), תוויות חסרות, מבנה |
| `anchor-missing` / `anchor-duplicate` | עוגן ליעד שלא קיים, ושני קישורים שונים לאותו יעד — אחד מהם שגוי |
| `attr-css-collision` | כלל CSS לפי תכונה שחל במקום לא מכוון (כפתור טעינה שנצבע כמושבת), עם הצבע שיוצא בפועל |
| `zoom-h-scroll` | גלילה אופקית בזום 200% (WCAG 1.4.4) ו-400% (1.4.10) |
| `h-scroll` | גלילה אופקית ב-375 / 768 / 1280 |
| `tap-target` | פקד מתחת ל-44px. קישור בתוך שורת טקסט פטור |
| סדר Tab | רשימת הפקדים לפי סדר ה-DOM — כך רואים שכפתור הקנייה הראשי אחרון |

## אחרי ההרצה — שני דברים שחובה לעשות

1. **תסתכל על הצילומים** (`Read` מציג תמונות): `*-mobile.png`,
   `*-desktop.png`, `*-zoom200.png`. שם נתפסים עברית משובשת, פריסה
   שנשברת, אייקון שלא קריא, והיררכיה שלא עובדת. הסקריפט לא רואה — אתה כן.
2. **תכתוב מה לא נבדק.** הסקריפט מחזיר את הרשימה בעצמו: קורא מסך אמיתי,
   מכשיר אמיתי במגע, והתאמה לספר המותג.

## מה זה לא

**ריצה נקייה היא לא אישור עמידה בת"י 5568.** בדיקה אוטומטית תופסת חלק
מכשלי הנגישות בלבד — היא לא יודעת אם הטקסט הגיוני, אם סדר הקריאה נכון,
או אם קורא מסך אמיתי מתנהג כמו התקן. "0 ממצאים" נכתב במסירה כ-"הבדיקה
האוטומטית לא מצאה ממצאים", לא כ-"נגיש".

`axe לא הכריע` בפלט = צריך עין אנושית, לא "עבר".
